# The Pool Problem（蓄水池问题）设计文档

> 日期：2026-08-09 · 状态：已确认 · 代码库：`poolproblem` · 产品名：**The Pool Problem**

## 1. 产品定位与名称

### 1.1 名称

- 正式品牌名：**The Pool Problem**
- 中文名：**蓄水池问题**
- CLI：`poolproblem`
- 代码库/目录名：`poolproblem`（App 内显示名可为 "The Pool Problem"）

### 1.2 名称谱系

该名字致敬经典数学应用题"蓄水池问题"（进水管、出水管、预测何时注满/排空）。这道题在英文世界没有唯一官方名称，常见叫法包括：

| 叫法 | 语境 |
|---|---|
| Cistern Problem | 数学史/学术（ProofWiki 有词条） |
| Pipes and Cisterns | 英联邦/印度考试辅导文化 |
| Swimming Pool / Pool Problem | 美国中小学应用题 |
| Tank / Water Tank Problem | 通用论坛与教材 |

品牌采用 **Pool Problem** 作为通用叫法中的专有名词，命名谱系记录于本文档。

### 1.3 主旨

> **The Pool Problem 是开发者的磁盘蓄水池。它把磁盘当作一道经典的蓄水池问题：测量进水管与出水管、预测何时会满、在源头治理，让可用空间始终稳定在健康水位，而不只是事后清理。**

### 1.4 目标用户

macOS 上的软件开发者（iOS/Android/Web/后端），主要痛点为：构建产物、模拟器快照、包管理器缓存等"可再生垃圾"持续消耗磁盘，磁盘在构建/测试的节骨眼上被打满，且清理后空间快速回涨、无从归因。

## 2. 心智模型：蓄水池

全部产品逻辑以蓄水池为心智模型：

| 蓄水池元素 | 产品对应 | 能力 |
|---|---|---|
| 池子容量 | 磁盘总容量 | 基础展示 |
| 当前水位 | 可用空间 | 菜单栏仪表 |
| 进水管 | 各产废源（Xcode 测试快照、微信缓存、npm install 等） | 空间账单：按工具/项目归因的流量计 |
| 进水流速 | 各源头每周/每日产生量 | 归因报告 + 异常涨速警报 |
| 出水管 | 清理速度（自动 + 手动） | 清理历史 |
| 何时溢流 | 预测磁盘何时满 | 满盘预测 |
| 目标水位线 | 保持可用空间 ≥ 30GB | 水线守护 |
| 水龙头 | 源头治理：限制产废（如 XCTestDevices 最多保留 N 个快照） | FSEvents 实时修剪 |
| 水质 | 脏水=可再生垃圾（可排），清水=使用中数据（不碰） | 安全分级 |
| 水位计校准 | APFS 克隆/稀疏文件导致的虚高读数 | 诚实计量 |

### 2.1 核心公式（满盘预测）

```
预计耗尽时间 = (当前可用空间 − 目标水位线) / 净消耗速率
```

其中净消耗速率由历史快照时间序列估计：**采用最近 7 天快照的线性拟合斜率；数据不足 7 天时，用已有天数的最小二乘拟合**。输出"按当前速度 N 天后会满"的可读提示，并给出拟合置信度（样本数过少时标注"估算"）。

## 3. 设计原则

1. **无干扰优先**：能静默就不打扰；开口仅在三种情况——异常增长、需要用户操作、定期小结。
2. **蓄水池思维**：处理对象是"流"（流速、水位、预测），不是"存量"（只报当前最大目录）。
3. **安全第一**：一切删除先 dry-run 预览；可再生才自动删；私人物品进回收站；全程留日志。
4. **尊重手头工作**：最近活跃的文件绝不自动动；绝不替用户杀进程；使用中的项标记"需先退出应用"。
5. **诚实计量**：报告"真实可释放空间"而非表面大小——扫描器必须感知 APFS 克隆共享与稀疏文件。
6. **面向开发者**：配方体系 + CLI + 未来 MCP，一切可脚本化、可机器读取。
7. **稳定水位而非一次性大扫除**：目标是长期维持可用空间，不是偶尔腾一次。

## 4. 核心能力

### 4.1 空间账单（归因）

按日/周/月归因：每个工具、项目、配方类别产生了多少 GB（如"Xcode 本周产生 23GB，其中测试快照 18GB"）。数据来自快照时间序列的差分。

### 4.2 回涨追踪

记录每次清理后各配方的大小回涨，回答用户最痛的"为什么又满了"：如"清理后 XCTestDevices 已回涨 15GB"。

### 4.3 满盘预测

按历史流速预测耗尽天数，在打断用户之前提前提醒（"按当前速度，5 天后磁盘会满"）。

### 4.4 源头治理

使用 FSEvents 实时监控已知产废点；当新垃圾出现（如新 XCTestDevice 创建、DerivedData 增长），立即按策略修剪最老部分（如"最多保留 5 个测试快照"）。这是与"定期扫描清理"的本质区别。

### 4.5 诚实计量

- 感知 APFS clone 文件（copy-on-write 共享块）与稀疏文件；
- 预估"真实可释放空间"（删除后实际能释放的量），避免 86GB 虚高只释放 5GB 这类误导。

### 4.6 水线守护

用户设定目标水位（默认可用空间 ≥ 30GB）。低于水线时，按"从最老开始"静默清理安全项，直到回到水线以上；无更多安全项但仍低于水线时，升级为通知提醒。

### 4.7 静默分级清理

安全分级见第 5 节。后台静默清理只处理 `safeWhileRunning` 且满足年龄阈值的项，不发逐项通知，仅写日志与更新菜单栏。

### 4.8 通知策略（静默优先）

- 静默清理：不通知；
- 增长警报：24 小时内增长 > 2GB，或相对增长 > 50% 且绝对值 > 500MB；
- 空间紧张：可用空间 < 20GB（默认，可调）提醒一次；
- 需要用户操作：水线以下且只剩 `requiresQuit`/`userConfirm` 项；
- 每周清理摘要（可关闭）。

## 5. 安全模型

### 5.1 安全分级

| 级别 | 含义 | 例子 | 后台静默 |
|---|---|---|---|
| `safeWhileRunning` | 进程运行时删了也无妨 | 旧 XCTestDevices、Xcode 日志、旧 ModuleCache、npm/uv 缓存、应用缓存 | ✅ |
| `requiresQuit` | 进程占用中删了可能出错 | 正在构建的 DerivedData、已启动的模拟器设备 | ❌ 提示"请退出 Xcode/Simulator" |
| `userConfirm` | 必须用户确认 | 自定义路径、下载目录、非可再生数据 | ❌ 仅提醒，进专家模式 |

### 5.2 删除策略（按类，方案 C）

- 可再生构建/缓存类：按各配方规则执行（回收站或彻底删除，默认彻底删除可再生项，自定义项进回收站）；
- 自定义路径：默认进回收站，需用户确认；
- 一切删除先 dry-run 预览（路径、大小、释放量）。

### 5.3 防干扰保护

- 最近 24 小时被修改过的文件不自动清理（保护进行中的构建/测试）；
- ProcessGuard 检测 Xcode/Simulator/微信/QQ 等进程占用，占用项跳过并提示；绝不自动杀进程；
- 白名单：用户指定路径永不清理。

### 5.4 日志

每次清理记录时间、路径、大小、方式（回收站/彻底），可查看最近清理历史；日志本身按年龄清理。

## 6. 配方库（v1）

| 类别 | 配方示例 | 默认策略 | 默认年龄 |
|---|---|---|---|
| Xcode 构建 | DerivedData、XCTestDevices、Archives、DocumentationCache | 可再生自动清 | XCTestDevices 3 天；DerivedData 7 天；其余 30 天 |
| 模拟器 | CoreSimulator 设备数据、旧版运行时 | 设备数据按年龄清；运行时只提示不自动删 | 30 天 |
| 包管理器 | npm/pnpm/uv/pip/CocoaPods/Homebrew 缓存 | 自动清 + 退出相关工具提醒 | 30 天 |
| 项目 | node_modules、build/dist（扫描 `~/develop` 及用户配置目录） | 只提示不自动删 | — |
| 通用安全项 | `~/Library/Caches`、废纸篓、EdgeUpdater 等已知可再生缓存 | 按年龄自动清 | 30 天 |
| 自定义路径 | 用户添加任意目录 | 默认回收站 + 确认 | 用户设置 |

## 7. 操控模式

### 7.1 傻瓜模式（默认）

开机自启后全自动：只处理"可再生且安全"的配方，按默认规则与水线执行，不打扰；通知仅出现在异常/需要操作/周报时。

### 7.2 专家模式

每个配方可单独开关、调整阈值/年龄、配置白名单、预览将删除的文件、手动"立即清理"。

## 8. 架构

### 8.1 目录结构

```
poolproblem/
├── DiskReservoirCore/          # Swift Package 库（无 UI）
│   ├── Recipes/                # 配方定义与注册
│   ├── Scanner/                # 扫描执行（含 APFS 克隆感知）
│   ├── Snapshot/               # 快照模型 + SnapshotStore
│   ├── Flow/                   # 流速计算、归因账单、回涨追踪、满盘预测
│   ├── Cleaner/                # 清理引擎、规则评估、ProcessGuard
│   └── Storage/                # 存储路径解析（App Group / Application Support）
├── PoolProblemApp/             # SwiftUI 菜单栏 App（无 Dock 图标）
├── PoolProblemWidgets/         # WidgetKit 扩展（macOS 14+）
├── PoolProblemCLI/             # 命令行（scan/suggest/clean/status，JSON 输出）
├── Docs/                       # 设计文档、MCP 未来规划
└── Package.swift / 工程文件
```

### 8.2 数据流

App 启动/开机自启 → 权限检查与引导（完全磁盘访问）→ 定时扫描（核心目录每次、家目录低频）→ 快照写入共享容器 → 增长检测/流速计算 → 需要时通知或按规则清理 → 菜单栏与小组件刷新。CLI 与 App 读写同一份配置与快照库，文件锁互斥。

### 8.3 存储

- 配置：UserDefaults（App）与共享 JSON（CLI 共用）；
- 快照历史：App Group 容器 `~/Library/Group Containers/<group-id>/` 下 JSON（Codable），App、小组件、CLI 共用；
- 并发：文件锁避免 App 与 CLI 同时写/清理。

### 8.4 权限

- App 不启用 App Sandbox（DMG 直投，功能需要）；
- 首次启动检测完全磁盘访问（尝试读取 `~/Library/Containers` 等受保护路径），未授权时引导到系统设置，并提供"跳过"降级模式（只扫普通可读目录）。

## 9. 小组件（WidgetKit，macOS 14+）

- 独立扩展进程，无法继承主 App 权限：只读共享容器里的最新快照；
- v1 单尺寸：剩余空间仪表（数字 + 色条）+ 最近 3 个可清理项 + "打开 App"按钮；
- 按钮走 App Intent，仅做打开/请求刷新，清理动作始终在主 App 执行；
- 每次扫描/清理后调用 `WidgetCenter.reloadAllTimelines()` 刷新。

## 10. CLI 与 MCP

### 10.1 CLI v1

```
poolproblem scan              # 扫描并输出各配方大小（--json 机器可读）
poolproblem suggest           # 建议可清理项与安全级别
poolproblem clean --dry-run   # 预览将删除内容
poolproblem clean             # 按规则执行清理
poolproblem status            # 当前水位、预测、最近清理
```

所有命令输出稳定 JSON schema（核心模型 Codable 序列化），CLI 与 App 共用核心库。

### 10.2 MCP（未来，不在 v1）

核心层保持无 UI 依赖 + JSON 稳定输出，未来用 MCP server 薄壳包装 `scan/suggest/clean/status`，供 AI Agent 直接调用。

## 11. 技术栈与分发

- Swift 6 / SwiftUI；macOS 14+；
- 单进程常驻 App（LSUIElement 菜单栏应用）+ SPM 核心库 + CLI；
- 分发：Developer ID 签名 + 公证 + DMG；第一版内部自用（ad-hoc 可跑），v1.0 正式分发；不上 App Store（沙盒限制无法实现系统级清理）；
- 自动更新：v1 不接入 Sparkle（内部自用阶段手动替换即可）；正式对外分发时再评估接入 Sparkle。

## 12. 错误处理与降级

- 扫描中断、权限被拒、磁盘满导致快照写不进、文件被占用：静默降级 + 菜单栏状态提示，不弹窗轰炸；
- 无 FDA 时降级为部分可读目录扫描，并提示功能不完整；
- CLI 与 App 并发互斥（文件锁），扫描期间不重复清理同一配方。

## 13. 测试策略

- Core 单测：配方解析、大小统计（fixture 目录）、APFS 克隆/稀疏感知（fixture）、流速/预测/归因计算、规则评估（年龄/白名单/阈值）、删除器注入（不真删）、JSON schema；
- CLI 集成测试：在 fixture 目录上跑 scan/suggest/clean/status，校验 JSON；
- App/小组件：手动测试 + 预览为主；
- 不依赖真实 Xcode 环境，用 fixture 模拟 DerivedData/XCTestDevices 结构。

## 14. 竞品对比与差异化

同类产品：Harbofly（macOS 菜单栏开发清理工具，开源，含 CLI/风险分级/触发式自动清理）、diskr、mcdu、DaisyDisk 等。

差异化（Harbofly 等不具备）：

1. **空间水线持续守护**：不是触发式清理，而是长期维持目标可用空间；
2. **增长检测/磁盘泄漏**：24h 异常涨幅归因报警；
3. **诚实计量**：APFS 克隆感知，报告真实可释放/真实回涨；
4. **静默分级清理**：`safeWhileRunning` / `requiresQuit` / `userConfirm` 三级；
5. **归因账单 + 回涨追踪 + 满盘预测**：基于快照时间序列，直接回答"空间去哪了、为什么又满了、何时会满"；
6. **源头治理**：FSEvents 实时修剪，垃圾产生即处理；
7. **MCP 路线**（未来）与桌面小组件。

## 15. v1 里程碑

1. **M1 Core**：配方库、扫描器（APFS 感知）、快照存储、流速/归因/预测、清理引擎、ProcessGuard；
2. **M2 CLI**：scan/suggest/clean/status + JSON；
3. **M3 App**：菜单栏面板、设置（傻瓜/专家）、通知、权限引导、开机自启；
4. **M4 Widget**：一档小组件；
5. **M5 打包**：DMG + 公证（内部自用可先行 ad-hoc）。

## 16. 明确不做（v1）

- iOS / watchOS 客户端（远程看板价值低，用户无法远程操作）；
- 联动岛 / 悬浮半透明层（预留数据流，后续新增 UI 壳）；
- MCP server（预留接口，v1 后做）；
- 自动杀进程；
- 通用磁盘清理工具定位（面向大众的下载/大文件扫描等）。
