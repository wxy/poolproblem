# M3 菜单栏 App 实现计划（The Pool Problem）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付常驻菜单栏 App：水位面板、一键智能清理、傻瓜/专家设置、通知、完全磁盘访问引导、开机自启；并让 scan 自动保存快照（CLI 同步闭环）。

**Architecture:** Xcode 工程（macOS 14+）的 App target 通过本地 SwiftPM 包依赖 `DiskReservoirCore`；UI 只做展示与编排，领域逻辑全部在 Core。菜单栏用 SwiftUI `MenuBarExtra`（无 Dock 图标，`INFOPLIST_KEY_LSUIElement=YES`）；后台扫描用 `Timer` 调度；通知用 `UNUserNotificationCenter`。

**Tech Stack:** Swift 6、SwiftUI、UserNotifications、ServiceManagement（SMAppService）、Xcode 26、macOS 14+。

## Global Constraints

- macOS 14+；App target `SWIFT_VERSION=6.0`；Bundle ID `com.poolproblem.app`；App Group `group.com.poolproblem.app`（StoragePaths 已默认）。
- 不启用 App Sandbox；完全磁盘访问通过系统设置授予（TCC），App 只做检测与引导。
- 领域逻辑（扫描/清理/预测）禁止写在 View 层；一律走 `AppService` → Core。
- 通知权限在首次需要时请求；用户拒绝则静默降级为菜单栏提示。
- 快照：`Scanner` 每次扫描后写入 `SnapshotStore`；CLI `scan` 同样落盘（M1 缺口，本计划补齐）。
- 提交规范：conventional commits；每个任务可构建（`xcodebuild build`）后才能提交。

- [ ] **Step 3: 清理编排**

```swift
func smartClean(dryRun: Bool) async -> CleanOutcome {
    let config = loadConfig()
    let result = try! Scanner().scan(recipes: RecipeRegistry.builtIn(), homeDirectory: NSHomeDirectory())
    let outcome = try! Cleaner(
        evaluator: RuleEvaluator(config: config),
        deleter: FileManagerFileDeleter(),
        inspector: PGrepProcessInspector(),
        logStore: CleanLogStore(paths: paths)
    ).run(scan: result, config: config, waterlineBytes: Int64(config.waterlineGB * 1_000_000_000))
    await scanNow()
    return outcome
}
```

`dryRun` 时在 View 层先展示 `suggest` 结果供用户确认，执行时传 `dryRun=false`（确认由 UI 承担）。
